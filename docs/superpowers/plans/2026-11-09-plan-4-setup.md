# Pocket Agent Plan 4: Setup, Key Storage, Notices, Phone Guidance and Voice

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stranger installs the APK and reaches a finished first task using only the app's own screens: in-app provider setup with an encrypted key, notices, phone guidance, voice input and the brand palette, replacing the build-time `local.properties` config.

**Architecture:** Every decision that can be made without Android lives in plain Kotlin in the new `setup/` package and is tested on the JVM (Tasks 1, 2, 5, 6, 8, 10). The Android parts (`SetupActivity`, `VoiceInput`, `PrefsKeyValueStore`, `KeystoreSecretBox`, the `AgentSession` wiring) only gather facts, draw Views and call the pure code. Storage goes through two small ports (`KeyValueStore`, `SecretBox`) so the "never a plaintext fallback" and "corrupt value means no key" rules are testable without a phone.

**Tech Stack:** Kotlin, coroutines, Android framework Views, Android Keystore and `SpeechRecognizer` APIs only (no new dependencies, no Robolectric, no `androidx.*`), JUnit 4, kotlinx-coroutines-test.

**Spec:** `docs/superpowers/specs/2026-11-09-s4-setup.md`. Also: main spec §7 to §9, security spec §2 (T7, T12) and §3, S2 spec §3 and §9 (`ProviderConfig`, `ProviderCheck`, presets), S3 spec §8 (the debug-only config this plan deletes).

## Global Constraints

- Carried from Plans 1 to 3: Kotlin only; packages `agent`, `llm`, `safety`, `playbook`, `device` and now `setup` import no `android.*` or `androidx.*` (`ArchitectureTest`); no telemetry; the API key is never logged, shown or committed; no logging at all (`Log`, `println` or a wrapper); commits are small, imperative, and end with the `Co-Authored-By` line; run `git status` before each commit.
- Dependencies stay exactly as allowed by `dependenciesMatchAllowlist`. Add none. Platform APIs only.
- Permissions stay `INTERNET` and `RECORD_AUDIO` only. No overlay permission, no `QUERY_ALL_PACKAGES`. `allowBackup="false"` and the data-extraction rules stay. `manifestMatchesAllowlist` passes unchanged. The only exported component is the launcher activity.
- Android's regex engine throws on `Pattern.UNICODE_CHARACTER_CLASS`; desktop Java does not (`ArchitectureTest.noRegexFlagsThatAndroidRejects` guards it). The JVM suite cannot see other Android-only failures either, so every Android class ends with `./gradlew :app:assembleDebug` and a line in the device checklist (Task 12).
- Key storage: AES-256-GCM, a non-exportable Android Keystore key, a fresh random 12-byte IV per save, IV plus ciphertext stored as one text value. A failed decrypt means "no key", never a crash. If a Keystore key cannot be created the key is not saved: **no plaintext fallback**. After saving, the field shows "Key saved" and a Replace button, no characters. `FLAG_SECURE` on the whole `SetupActivity`.
- Voice: `SpeechRecognizer`, no language set (the phone's language), `EXTRA_PREFER_OFFLINE`, partial results fill the box, the user presses Go. `RECORD_AUDIO` is requested only in setup code, never on the task screen. Task text cap 2,000 characters and the empty-text rule are unchanged.
- Palette (spec §7): background `#090A10`, surface `#121520`, border `#1E2333`, blue `#1E6FFF`, subdued blue `#1A2B4C`, orange `#FF8544`, text `#F8F9FC`, muted `#8E95A5`. Applies to every screen and card; the bubble keeps its state colours except the running ring, which is brand blue. Dark text on orange; labels on solid blue are bold and at least 18 sp; blue is not used for small body text; Allow and Decline are identical in size, weight and colour.
- Setup steps in order: `NOTICE`, `PROVIDER`, `MODEL_CHECK`, `ACCESSIBILITY`, `MICROPHONE` (optional), `BUBBLE`, `TEST_TASK`. The bubble flag defaults to off.
- Test phone for the exit gate: Nothing A059, Android 16. Parallel work uses worktrees created by hand from the current branch head (`git worktree add -b <name> .claude/worktrees/<name> HEAD`).

## Review Focus

1. **A stored key that cannot be opened** (cleared Keystore, tampered or truncated value): `load()` returns no config, setup asks for the key again, nothing crashes. Tested in Tasks 2 and 3.
2. **Editing the provider, key or model after a passed check or test task:** both are invalidated, so a stale "works" never survives. Tested in Task 2.
3. **A Keystore that cannot create a key:** `save` fails with a reason and stores nothing, in particular no unencrypted key. Tested in Task 2.
4. **Accessibility reported "enabled" in different spellings** (full or short component name, other services in the list, empty or null setting): the checklist must still be right. Tested in Task 10.
5. **A custom base URL whose host changes after the warning was accepted:** the warning is asked again for the new host. Tested in Task 1.

**Files:**
- Create: `setup/Storage.kt`, `setup/StoredConfigRepository.kt`, `setup/SetupSettings.kt`

**Interfaces:**
- Consumes: `ProviderConfig`, `ProviderKind` (package `llm`).
- Produces:
```kotlin
interface KeyValueStore {
    fun getString(key: String): String?
    fun putString(key: String, value: String?)      // null removes the key
    fun getBoolean(key: String, default: Boolean): Boolean
    fun putBoolean(key: String, value: Boolean)
}
class SecretBoxException(message: String) : Exception(message)
interface SecretBox {
    fun seal(plain: ByteArray): ByteArray            // IV + ciphertext; throws SecretBoxException when it cannot
    fun open(sealed: ByteArray): ByteArray?          // null when it cannot be opened for any reason
}
object SealedValue {
    fun encode(bytes: ByteArray): String             // "v1:" + Base64 (java.util.Base64), no line breaks
    fun decode(text: String?): ByteArray?            // null for null, blank, wrong prefix, bad Base64, empty payload
}
sealed interface SaveResult { data object Saved : SaveResult; data class Failed(val reason: String) : SaveResult }
interface ConfigRepository {
    fun load(): ProviderConfig?                      // null when nothing saved or the key cannot be opened while one is needed
    fun save(config: ProviderConfig): SaveResult
    fun clear()
    val modelCheckPassed: Boolean
    fun markModelCheckPassed()
    var testTaskDone: Boolean
}
class StoredConfigRepository(store: KeyValueStore, box: SecretBox) : ConfigRepository
class SetupSettings(store: KeyValueStore) {
    var noticeAccepted: Boolean
    var acceptedCustomHost: String?
    var microphoneAsked: Boolean
    var bubbleOn: Boolean                            // default false
}
```
Stored keys (private constants): `config.kind`, `config.baseUrl`, `config.model`, `config.images`, `config.effort`, `config.contextTokens`, `config.maxOutputTokens`, `config.id` (value `"default"`), `config.apiKey` (a `SealedValue`), `check.passed`, `testTask.done`, `settings.notice`, `settings.customHost`, `settings.micAsked`, `settings.bubble`. `save` seals the key first; if `seal` throws, return `Failed(reason)` and write nothing. An empty key (local server) is stored as an absent `config.apiKey` and loads as `""`. `save` clears `check.passed` and `testTask.done` when any of kind, base URL, key, model or images differs from what was stored. `load` returns null when `config.kind` is missing, when a stored kind name is unknown, or when `config.apiKey` is present but `decode`/`open` gives nothing.
